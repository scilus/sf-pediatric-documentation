## **Checklist**

Before running the pipeline, make sure you have completed the following:

<Steps>

1. **Prerequisites installed?**
   
   Verify that `nextflow` and either `docker` or `apptainer` are installed and working. See the [installation guide](/sf-pediatric/guides/installation) for detailed instructions.

2. **BIDS data validated?**
   
   Your data must be organized in BIDS format with the `participants.tsv` file containing the **age** column. See the [inputs guide](/sf-pediatric/guides/inputs) for details.

3. **FreeSurfer license available?**
   
   :::caution
   If you plan to use the **segmentation profile**, you **must** have a valid FreeSurfer license. Get one [here](https://surfer.nmr.mgh.harvard.edu/registration.html) (free for academic use). You'll specify the path with `--fs_license /path/to/license.txt`
   :::

4. **Know which analysis you want to run?**
   
   Decide which profiles you need based on your research goals. See the [Understanding the profiles](/sf-pediatric/guides/profiles) guide.

5. **Will you have access to the internet during processing?**

   Internet access is not required to run the pipeline. However, by default, the pipeline will download some dependencies during execution. If you plan on running it on a machine without internet access (e.g., an HPC cluster), head over to the [running with no internet access](/sf-pediatric/guides/nointernet/) section.

</Steps>

## **A simple example**

If you're new to the pipeline, start with this basic command for diffusion MRI preprocessing and tractography:

:::note[Assumptions]
By default, the pipeline assumes two important things:

<Steps>
1. **B-values ≤ 1200 s/mm²** for DTI fitting.

2. **B-values ≥ 700 s/mm²** for fODF fitting.
</Steps>
**If your acquisition protocol does not fit those assumptions**, you can change the pipeline behavior. For more information, see [this section](/sf-pediatric/guides/usage/#shell-selection-for-dti-and-fodf-models).

:::

<Tabs>
<TabItem label="Command">
```bash
nextflow run scilus/sf-pediatric -r 0.2.2 \
   --input /absolute/path/to/your/BIDS_directory \
   --outdir /absolute/path/to/results \
   -profile docker,tracking \
   -resume
```
</TabItem>
</Tabs>

:::tip[What does this do?]
This command will:
- Download and run the pipeline version 0.2.2
- Process all subjects in your BIDS directory using the `tracking` profile
- Save the results to your specified output directory
- Use Docker containers
:::
:::tip[Need help choosing profiles?]
If you're unsure which profiles to use, check out the [understanding the profiles](/sf-pediatric/guides/profiles) guide for detailed explanations and common recipes.
:::

## **Required parameters**

Every pipeline run needs **at least** these three parameters:

<Steps>
1. **`--input`** - Path to your BIDS directory
   
   Your data must follow [BIDS format](/sf-pediatric/guides/inputs) with a `participants.tsv` file containing an `age` column.

2. **`--outdir`** - Where to save results

   Results can be large (several GB per subject), so choose a location with sufficient space. We recommend naming the output directory with the version number (e.g., `--outdir /path/to/results/sf-pediatric-v0.2.2`)

3. **`-profile`** - Which profiles to run

   ```bash
   # Always include a container system (docker/apptainer) + processing profiles
   -profile docker,tracking
   -profile apptainer,tracking,segmentation,connectomics
   ```

   See the [profiles guide](/sf-pediatric/guides/profiles) for detailed information on choosing profiles.

   :::tip[Want to speed up your processing using a GPU?]
   `sf-pediatric` supports using GPUs to speed the `eddy` and `tracking` processes. If you have access to a GPU, you can add the `-profile gpu,...` to your command line. For more information, please see the [understanding the profiles](/sf-pediatric/guides/profiles) section.
   :::
</Steps>

:::note[Using a custom atlas]
`sf-pediatric` supports the use of user-defined custom atlases, for more information, please see the [Using a custom atlas section](/sf-pediatric/guides/atlases/).
:::

## **Important optional parameters**

### **Shell selection for DTI and fODF models**

:::caution[Check your b-values!]
As mentioned above, the pipeline assumes by default:

<Steps>
1. **B-values ≤ 1200 s/mm²** for DTI fitting.

2. **B-values ≥ 700 s/mm²** for fODF fitting.
</Steps>

**Does your data have different b-values?** (e.g., HCP protocol with b-values of 1500 and 3000 s/mm²)

If your data does not match the above-mentioned assumptions, you **MUST** specify which shells to use, or the pipeline will likely fail. Follow the instructions below.
:::

#### **How to specify shells:**

```bash
# For HCP-like protocol (b-values: 1500 and 3000)
nextflow run scilus/sf-pediatric -r 0.2.2 \
   --input /path/to/BIDS \
   --outdir /path/to/results \
   --dti_shells "0 1500" \
   --fodf_shells "0 1500 3000" \
   -profile docker,tracking \
   -resume
```

For more details, see [`--dti_shells`](/sf-pediatric/guides/parameters/#dti-options) and [`--fodf_shells`](/sf-pediatric/guides/parameters/#fodf-options) parameters.

### **Selecting specific subjects to process**

Sometimes, you might want to process only a subset of subjects from your complete BIDS dataset. This is entirely possible using the [`--participant_label`](/sf-pediatric/guides/parameters/#inputoutput-options) parameter.

```bash
# Process only sub-01 and sub-02
nextflow run scilus/sf-pediatric -r 0.2.2 \
   --input /path/to/BIDS \
   --outdir /path/to/results \
   --participant_label "sub-01,sub-02" \
   -profile docker,tracking \
   -resume
```

:::tip[Selecting a large number of subjects]
For multiple subjects or complex configurations, using an external `params.yml` file containing all CLI parameters is recommended (see the [advanced usage](/sf-pediatric/guides/advanced/) section for more information).
:::

:::tip[All modifiable parameters]
While we only overviewed the most common parameters here, `sf-pediatric` can be customized even further through various additional parameters that can all be supplied through the command line (as shown above) or through an external `params.yml` file (see [advanced usage](/sf-pediatric/guides/advanced/)). The **complete list** of modifiable parameters can be found in the [parameters](/sf-pediatric/guides/parameters/) section.
:::

## **Understanding pipeline outputs**

:::tip[Something went wrong?]
If for some reason, the pipeline's execution stopped early, or do not start, head over to the [troubleshooting](/sf-pediatric/guides/troubleshooting/) page!
:::

The pipeline will create the following structure in your current working directory (assuming your `--outdir` is located in this directory):

<FileTree>
- work/                           # Temporary files (can be deleted after successful run)
- sf-pediatric-v0.2.2/            # Your results (specified by --outdir)
  - dataset_description.json
  - participants.tsv
  - multiqc/                      # Quality control reports
  - sub-01/
    - ses-01/
      - anat/                     # Anatomical images (T1w/T2w processing)
      - dwi/                      # Diffusion images and tractography
      - figures/                  # QC visualizations
      - multiqc/                  # Subject-specific QC
      - xfm/                      # Image transformations
- .nextflow.log                   # Log file (check this if errors occur)
- .nextflow/                      # Nextflow cache (enables -resume)
</FileTree>

For a detailed description of each output file, see the [outputs guide](/sf-pediatric/guides/outputs).
